# App Flow Document for codeguide-invoice-module

## Onboarding and Sign-In/Sign-Up
When a new user arrives at the application, they first see a simple landing page that explains the invoice management system and invites them to sign up or log in. To create a new account, the user clicks the Sign Up button and is taken to a registration form where they enter their email address and a password. After submitting the form, they receive a verification email and follow the link to confirm their account. Once confirmed, the user is automatically signed in and directed to the main dashboard.

Existing users can click the Sign In link on the landing page, enter their email and password, and submit the form to access their account. If the user forgets their password, they click the Forgot Password link, enter their registered email, and receive a password reset email. Following the reset link takes them to a page where they set a new password, and upon completion they can sign in normally. All sign-in and sign-up pages provide clear feedback on validation errors, such as invalid email format or incorrect password, and guide the user to correct any issues.

To sign out, the user clicks a Logout button typically found in the header or sidebar. This action ends the session and redirects the user back to the landing page. Behind the scenes, session cookies are cleared and the user must log in again to re-enter the protected areas of the app.

## Main Dashboard or Home Page
After signing in, the user lands on the dashboard home page, which serves as the central hub for all invoice management tasks. The layout features a left-hand navigation bar listing key sections, including Invoices, Settings, and Log Out. At the top, a header displays the user’s name and role, and offers quick access to account notifications. The main area of the dashboard shows an overview panel with metrics such as total invoices, overdue invoices, and upcoming due dates.

From this dashboard home, the user can click on the Invoices link to view all invoice records, or click Settings to update personal information and notification preferences. The sidebar collapses or expands on demand, and the user can hover over icons or click labels to navigate between pages. The design maintains consistency through a shared set of UI components, ensuring the user always knows where they are and how to move to other parts of the app.

## Detailed Feature Flows and Page Transitions
When the user selects Invoices from the sidebar, they arrive at the Invoice List page. The application automatically fetches data from the `/api/invoices` endpoint, which returns a list of invoices filtered by the user’s role: customers see only their own invoices, while admins see all invoices. The list is displayed in a table with sortable columns such as invoice number, client name, amount, due date, and status. The user can scroll through the table or use search and filter controls to narrow down the results.

Clicking on an invoice row takes the user to the Invoice Detail page at `/dashboard/invoices/[id]`. This page shows full information for the selected invoice, including line items, payment history, and any attached notes. If the signed-in user has the admin role, an Edit button appears on this page. When clicked, it brings up the Invoice Form in edit mode, pre-filled with the existing invoice data.

The Invoice Form page, accessible at `/dashboard/invoices/new` for creating or via the Edit button for updating, guides the user through entering client information, item descriptions, quantities, prices, and due dates. The form uses inline validation and displays error messages if required fields are missing or formatted incorrectly. Upon submission, the form makes a POST request to `/api/invoices` to create a new record or a PATCH request to `/api/invoices/[id]` to update an existing one. After a successful save, the user is returned to the Invoice Detail page to review changes.

When customers click a Pay button on their invoice detail page, they are directed to an external payment provider. After payment completion, the provider sends a webhook to the `/api/payments/webhook` endpoint. This webhook route validates the payload, updates the invoice status to "Paid" in the database, and triggers an email receipt. The next time the customer refreshes their Invoice Detail page, they see the updated status and payment confirmation.

Overdue invoice reminders are handled by a scheduled serverless function at `/api/cron/send-reminders`. An external cron job calls this endpoint daily. The function queries for invoices past their due date that have not been paid, generates personalized reminder emails using the email service in `lib/email.ts`, and sends them to the appropriate clients. Any failures in sending are logged for later review.

## Settings and Account Management
The Settings section allows users to manage their personal information and notification preferences. Users navigate to `/dashboard/settings` to view and edit their profile details such as full name, email, and password. Changing the password requires entering the current password and the new password twice for confirmation. These updates are sent to `/api/users/profile` as a PATCH request. Successful updates display a confirmation message, while validation errors highlight the specific fields to fix.

Notification settings let users opt in or out of email reminders for upcoming or overdue invoices. Toggling these options updates the user’s preferences in the database, and the changes take effect immediately. After saving settings, the user can return to the main dashboard by clicking the Home link in the sidebar.

## Error States and Alternate Paths
If the user attempts to access a protected route without logging in, the application automatically redirects them to the sign-in page with a message prompting them to sign in first. When users enter invalid credentials during sign-in, an error banner appears explaining that the email or password is incorrect. During sign-up, if the email is already in use or the password fails complexity requirements, inline messages appear next to the relevant fields.

Should a user try to perform an action they are not authorized for—such as a customer accessing another customer’s invoice or editing an invoice without admin privileges—the system responds with a 403 Forbidden status and displays an on-screen message stating they do not have permission. In the event of network failures or server errors when fetching or submitting data, a notification bar appears advising the user of connectivity issues and offering a Retry button. For unexpected system errors, a generic error page is shown with a link back to the dashboard.

If the payment webhook verification fails—due to an invalid signature or missing data—the webhook route returns a 400 error, logs the incident for review, and sends an alert to the administrators. For the reminder cron job, any email sending errors are recorded, and the function continues processing remaining invoices, ensuring a single failure does not halt the entire batch.

## Conclusion and Overall App Journey
From the initial landing page, a new user can sign up or log in, recover a password, and arrive at a clear dashboard overview. Customers quickly access their invoices, review details, and make payments. Admins benefit from full visibility of all invoices, with the ability to create, edit, and send reminder emails. Account settings remain accessible at any time for updating personal information or notification preferences. Error messages guide the user through common pitfalls, and serverless cron jobs and webhooks automate critical background tasks. Together, these flows create a seamless experience for managing invoices, tracking payments, and ensuring timely reminders, all within a cohesive and intuitive interface.
